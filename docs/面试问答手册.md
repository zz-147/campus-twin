# 面试问答手册（校园网络数字孪生运维平台）

> 用途：面试前 10 分钟快速过一遍，面试中按“要点 + 口语化开头”展开。
> 项目定位：**个人独立开发**的 AI 全栈 / AI Agent / 大模型应用项目，核心是“真实网络数据 → 运维后端 → Agent 编排 → 3D 可视化”的完整闭环。
> 原则：数字只背本手册里的真实口径；不确定的地方说“这块建议现场演示/看代码与文档”，**不编造**。

## 0. 数字口径（先背这张表，避免两个“23”说混）

| 项 | 真实数字/口径 |
|---|---|

**节点数口径**：手册按“**12 个核心节点**”讲（classify / 角色节点 / aggregate / wait_confirm / execute_action）；W13 接入 MCP 后代码里为 **14 个节点**，如面试官追问节点数，以现场 `graph.py` 为准，并主动说明“能力扩展会加节点”。

## 一、面试前 10 分钟准备清单

### 1.1 环境/端口（提前 5 分钟起好）
- 后端 `http://127.0.0.1:8000`、Agent `http://127.0.0.1:8100`、前端 `http://127.0.0.1:5173`、MCP Bridge `http://127.0.0.1:8200`。
- 健康检查（口述即可，不必都投屏）：`GET /api/health`（后端 / Agent，看 `driver=netcon`、`provider_ready`、`mcp_bridge.available`）。
- MCP Server 是 stdio 形态，不占端口，用 `verify_client.py` 或 Agent 工具验证。

### 1.2 90 秒演示路径（按这个顺序讲，别乱点）
1. **3D 大屏**：4 楼栋、5 台设备健康、6 台终端在线 → 说明“数据不是截图，是 5 秒轮询的真实 NC 数据”。
2. **路径追踪**：PC-JX1 → Server-1，展示 4 跳 hop 链 + 3D 发光路径；口述 `complete/partial/failed` 与断点定位。
3. **告警面板**：切“按根因分组”，展示 2 组、根因设备、被上游抑制条数（说明“抑制只是展示层，不删告警”）。
4. **AI 面板**：
   - 问“现在整体网络状态怎么样” → 流式回答；
   - 问“把已恢复的告警清空” → 规则路由 `route_source=rule` + **pending action 危险卡片** → 取消（强调不自动执行）；
   - 问“宿舍楼要接入一台 2960，上联核心怎么配置” → RAG 命中 5 条 `[K1]-[K5]`；
   - 问“帮我读一下 configs/core-3650.txt 里 VLAN 配置” → MCP filesystem 读真实文件。
5. 若被追问“没网/没 key 怎么办”：切 mock + fixture，全部离线可跑；MCP 未启动时工具 `ok=false` 中文降级并明确不可用。

### 1.3 必背数据（面试官最常问）
- 数据：5 台网络设备全 Managed、6 台主机、5 节点 4 链路、5 秒周期、4 栋楼。
- 后端：7 条检测规则、NC 滞后 >3 分钟、双时钟差约 10 分钟。
- Agent：12 核心节点、23 工具（17+6）、38 场景、100%×4 指标、2600+ token 事件、18 知识块。
- MCP：Server 10/4/3；Bridge 外部 23（14+9）。
- 测试：171 / 256 / 30 / 10。

### 1.4 演示失败预案（提前想好，现场不慌）
- 后端挂了：Agent 切 `AGENT_DATA_SOURCE=fixture` + `LLM_PROVIDER=mock`，工具走合成快照，回答会明确标注数据源。
- LLM key/网络挂了：切 mock；先讲清“mock 是规则 baseline，不是模型能力”。
- MCP Bridge 没起：Agent 会返回“MCP Bridge 未启动或不可达”，这本身也是可展示的**优雅降级**。
- 前端异常：直接切 Agent 的 `POST /api/chat` / `/api/chat/stream`（Swagger `/docs` 可现场发请求）。

## 三、项目讲解模板（3 分钟，问题→方案→量化→深度钩子）

**① 问题（20 秒）**：校园网运维数据散落在 NC/PT/告警/指标里，排障靠人翻；大屏缺交互；LLM 直接接进来容易幻觉、不可控。
**② 方案（60 秒）**：三层——真实数据后端（采集/检测/告警生命周期）→ Agent 编排（LangGraph 多 Agent + 23 工具 + RAG + MCP + SSE + 人工确认）→ 3D 前端（路径/告警/AI 面板）。
**③ 量化结果（40 秒）**：5 设备 6 主机 5 节点 4 链路、5s；171/256/30/10 测试；38 场景双引擎 100%，自动执行违规 0；SSE 2600+ token；RAG 18 知识块、引用可追溯；写操作全部 pending + 10 分钟 TTL + CAS。
**④ 深度钩子（60 秒，选 1–2 个）**：
- **LangGraph interrupt 的“节点重跑”陷阱**：恢复时节点会从头执行，所以我把 `wait_confirm` 做成纯读 + interrupt，真正执行放在 `execute_action`，避免重复副作用。
- **规则优先路由 + 截断回归**：真实 LLM 路由有随机性，写操作改为规则短路；后来发现真实库 37 条告警让工具返回超 20k 被截断，steward 拿不到 cleared 列表，于是改为 summary/limit=1 取真实数量，28 行修复 + 8 条回归测试。
- **MCP 版本隔离**：Agent 是 3.9，mcp SDK 要 3.14；没有硬升 Agent，而是独立 3.14 Bridge + HTTP，Agent 只依赖一个 HTTP 契约。

## 四、高频问题分类（每题：回答要点 + 口语化开头）

### A. 项目整体（6 题）

**A1. 为什么做这个项目？**
- 要点：真实痛点（NC 告警+拓扑排障费劲、大屏缺交互）；验证 LLM 在真实数据闭环里的可控落地；个人项目可控范围大，能完整覆盖数据/后端/Agent/前端/测试。
- 口语化：“我最早不是想做一个‘AI 聊天框’，而是想验证一句话——大模型能不能拿着真实的网络数据，给出可解释、可确认的排障结论。”

**A2. 真实数据怎么保证？**
- 要点：NC Real World Access REST API 采集；5 设备全 Managed、6 主机、5 节点 4 链路；5 秒轮询；后端检测/告警/指标都落库；Agent 工具只读后端，不直接碰 PT。
- 口语化：“我的原则是‘Agent 不直接连网络设备’，所有数据先经后端采集落库，Agent 只读 API，这样可审计、可复现。”

**A3. 最大难点是什么？**
- 要点：不是调模型，是**数据与动作的确定性**：NC 清除滞后 >3 分钟、双时间基准约差 10 分钟；真实 LLM 路由波动；长告警导致工具结果截断；interrupt 恢复节点重跑。
- 口语化：“最难的是让系统‘稳定地正确’，不是‘偶尔答得漂亮’，比如告警滞后和路由随机性都会在演示时致命。”

**A4. 你的角色/贡献？**
- 要点：个人项目，独立完成；从需求、架构、后端、Agent、MCP、前端到测试/演示脚本；核心决策是“后端做真数据、Agent 做可控编排、前端做可演示”。
- 口语化：“这个项目是我独立从 0 到 1 做的，所以每个模块我都能讲到代码级取舍。”

**A5. 成果怎么量化？**
- 要点：5/6/5/4 数据规模、5s；171/256/30/10 测试；38 场景双引擎 100%×4；自动执行违规 0；SSE 2600+ token；RAG 18 块；MCP 10/4/3 + 外部 23。
- 口语化：“我不太喜欢只说‘支持流式、支持 RAG’，更愿意给数字：多少设备、多少测试、多少场景、多少 token 事件。”

**A6. 如果只能讲一个亮点？**
- 要点：**写操作的人机确认闭环**：规则确定性路由 → pending action 卡片 → interrupt 暂停图 → 用户确认/取消 → 恢复执行或终止，CAS 防重 + 10 分钟 TTL + 审计。
- 口语化：“我会讲‘危险操作怎么被安全地交给 AI’，因为它把 Agent 从 demo 拉到了可运维。”

### B. LangGraph / Agent（9 题）

**B1. 为什么用 LangGraph，StateGraph 原理是什么？**
- 要点：`StateGraph` + TypedDict 状态；节点返回增量；条件边负责路由；编译时绑定 checkpointer；相比线性链，适合“路由 + 循环 + 人工中断”的流程。
- 口语化：“我把它理解成一张可持久化的状态机：每个节点只做一件事，状态在节点间流动，条件边决定下一步。”

**B2. 为什么不用 LangChain AgentExecutor？**
- 要点：AgentExecutor 是黑盒 ReAct 循环，难做确定性路由、Send 并行、逐 action 的 interrupt/resume、细粒度 trace；自建图可控性更好，且能保留 plan/steps 给前端。
- 口语化：“AgentExecutor 适合快速做 Demo，但我要的是‘可控编排’，所以最后选了显式 StateGraph。”

**B3. interrupt() 底层怎么工作？**
- 要点：节点内调用 `interrupt(payload)` 暂停图、写 checkpoint；恢复用 `Command(resume=value)`；**节点会从头重跑**，所以副作用必须放在 interrupt 之后（我把执行放到 `execute_action`）。
- 口语化：“它是‘暂停 + 持久化 + 带值恢复’，不是简单阻塞。我踩过节点重跑的坑，所以 wait_confirm 里只做纯读和 interrupt。”

**B4. checkpointer 的作用？thread_id 为什么是 conversation_id？**
- 要点：每个 superstep 存档；`thread_id=conversation_id` 让多轮续聊、进程重启后能恢复暂停图；`snapshot.next` 判断是否停在 interrupt；本地 SqliteSaver 适合单机演示。
- 口语化：“它让一次对话变成一个可恢复的 thread，用户关掉页面再回来，图和待确认操作还在。”

**B5. Send 并行怎么做的？**
- 要点：classify 的条件边返回 `list[Send(role, payload)]`；多个 role 节点并行执行；状态用合并 reducer 汇总；aggregate 等所有分支后统一生成 plan/actions。
- 口语化：“一个问题拆成多个子任务时，我不是串行等，而是用 Send 把它们并到同一轮里跑，再汇总。”

**B6. 多 Agent 怎么路由？**
- 要点：规则优先层先匹配（写操作/路径/MCP/接入等）；未命中回退启发式/LLM；plan ≤3；每个 role 节点复用同一套工具白名单；trace 保留 plan/steps/route_source。
- 口语化：“先确定性规则，再让模型兜底，避免‘同一个问题两次回答走不同路’。”

**B7. 怎么防死循环/无限工具调用？**
- 要点：图 `recursion_limit=50`；诊断 max_steps=6；单步工具调用上限 8；plan 最多 3；工具失败返回 ok=false 回填而不是抛异常；规则短路减少模型绕路。
- 口语化：“我从图级、步级、工具级三层设上限，最坏情况也会停下来给解释。”

**B8. 工具失败怎么处理？**
- 要点：统一 envelope `ok/summary/data/error`；不抛异常；错误回填给 LLM；MCP Bridge 不可用给中文提示；评测里工具错误率也会统计，避免“失败被隐藏”。
- 口语化：“工具失败不是异常，是可观测数据，Agent 必须基于失败信息诚实回答。”

**B9. 为什么加“规则优先路由”？**
- 要点：真实 LLM 对“把已恢复的告警清空”偶尔不走 steward，演示不可接受；写操作/路径等先规则短路，trace 标 `route_source=rule`；规则带反例保护（“删除告警后为什么还在”仍走诊断）；补 5 次/3 次一致性测试。
- 口语化：“这一步不是为了炫技，是因为演示时真实 LLM 路由抖过一次，我把它变成确定性工程问题。”

**B10. 为什么用 SqliteSaver，不用 Redis/PostgreSQL checkpointer？**
- 要点：单机演示、状态量小；SQLite 零运维、文件可备份；生产多实例会换 Postgres/Redis，并处理并发写、TTL、恢复一致性。
- 口语化：“当前阶段我优先‘能恢复、能演示’，不是‘能扛并发’，边界我会主动说清。”

### C. RAG / 流式（7 题）

**C1. 为什么不上向量库？**
- 要点：语料只有 18 个知识块，规模小；要求离线、可解释、零运维；BM25 可解释、无 embedding 成本；工程上“先解决问题再上复杂度”。未来可换 pgvector。
- 口语化：“18 个块上向量库是杀鸡用牛刀，我更想要可解释、可离线复现的检索。”

**C2. BM25-lite 具体怎么做？**
- 要点：中文按字符 unigram+bigram；英文/数字切 token；标题/来源加权；BM25(k1=1.5,b=0.75) + 短语 bonus；疑问停用词过滤；min_score 阈值保证无命中返回空。
- 口语化：“我没有直接调库，而是按中文短查询的特点做了 bigram + 关键词加权的轻量实现。”

**C3. 怎么评测检索？**
- 要点：单测验证命中/排序/无结果/引用真实；38 场景加 3 个 RAG 场景（配置引用、NC 约束、无命中不编造）；trace.retrieval 记录 query/hits/score；答案引用 `[K1]` 可回查 chunk id。
- 口语化：“我不只看‘答得像不像’，而是看引用能不能回到真实知识块，以及无命中时敢不敢说不知道。”

**C4. SSE 怎么实现？**
- 要点：`POST /api/chat/stream` 返回 `text/event-stream`；事件 meta/status/tool/token/action/done/error；异步生成器；真实 LLM 用 LangChain `model.stream` 逐 token，mock 按 10–30 字切片；断开时停止推送并清理。
- 口语化：“流式不是把整段答案切碎发，而是要把‘思考阶段、工具、token、action、完成’都变成事件。”

**C5. 流式失败/断开怎么办？**
- 要点：异常只发 error 事件，不影响非流式 `/api/chat`；断开时 cancel 任务、清理 token 回调；done 里的 answer 是完整答案，token 拼接应与之一致（实测一致）。
- 口语化：“我把流式当‘降级路径’设计：它挂了，非流式仍然可用。”

**C6. token 成本怎么控制？**
- 要点：工具只读、RAG top5、诊断 max_steps=6、plan≤3；流式不重复生成；真实 LLM 的 polish 可关（`AGENT_POLISH_LLM=0`）；mock 模式零成本回归。
- 口语化：“成本控制不是砍功能，而是控制步数、上下文和额外调用，能流式就不二次生成。”

**C7. 引用和幻觉怎么保证？**
- 要点：RAG 无命中明确说“知识库无相关内容”；回答只能用工具/知识块事实；写操作必须确认；工具失败不编造；trace 可审计。
- 口语化：“我的底线是‘不知道就说不知道’，这比答得漂亮重要。”

**C8. 流式和 RAG 同时用，会不会冲突？**
- 要点：不冲突；RAG 在节点内先检索、再生成，token 流式只负责输出；引用在 done.answer 里完整保留；trace 同时记 retrieval 和 token 事件。
- 口语化：“RAG 决定‘依据什么’，流式决定‘怎么交给用户’，它们是两条正交的链路。”

### D. MCP（7 题）

**D1. MCP 是什么？**
- 要点：Model Context Protocol，标准化 Host/Client/Server 之间发现和调用 tools/resources/prompts 的协议；JSON-RPC（stdio/HTTP）；让外部能力可插拔，不用为每个工具改 Agent 代码。
- 口语化：“可以把它理解为 AI 应用的 USB-C：工具、资源、提示词用统一协议接进来。”

**D2. tools/resources/prompts 区别？**
- 要点：tools 是可调用动作；resources 是可读上下文（URI）；prompts 是标准提示模板；Server 自建 10 tools/4 resources/3 prompts（设备/拓扑/告警/路径/场景/审计；campus://scene、campus://topology、docs 资源；排障/接入 prompts）。
- 口语化：“工具是‘做’，资源是‘读’，提示词是‘怎么问’，三者组合才是完整 MCP Server。”

**D3. 为什么做双向（Server + Client）？**
- 要点：Server 把平台 10 个只读能力暴露给 Claude Desktop/Cursor；Client 桥把外部 filesystem/memory 接回 Agent；两个方向验证“平台既能被调，也能调别人”。
- 口语化：“只做 Server 是‘能力输出’，加 Client 才是‘生态互操作’，这两个方向我都想打通。”

**D4. 为什么 Python 3.9/3.14 版本隔离？**
- 要点：mcp SDK 需要更高 Python，Agent 是 3.9；不硬升整个 Agent，独立 3.14 Bridge 用 HTTP 解耦；代价是进程/端口/日志多一层，换来稳定和可独立升级。
- 口语化：“这是典型的‘隔离变化’：把版本冲突关在一个进程里，Agent 只依赖 HTTP 契约。”

**D5. MCP 安全边界？**
- 要点：Bridge 只听 127.0.0.1；filesystem 只读白名单 configs/docs（write/edit/move 拒绝）；memory 只写本地；所有调用写日志；Agent 侧工具只读语义。
- 口语化：“MCP 能力很强，所以我把‘能写哪里’做成白名单，而不是靠模型自觉。”

**D6. MCP 与 function calling 的区别？**
- 要点：function calling 是模型和宿主应用之间的工具调用协议；MCP 是跨进程/跨宿主的工具/资源/提示标准；两者结合：原生工具用 function calling，外部工具走 MCP 桥。
- 口语化：“function calling 解决‘模型怎么调工具’，MCP 解决‘工具怎么被不同 AI 客户端复用’。”

**D7. 为什么自建 MCP Server？**
- 要点：把平台能力标准化，Claude Desktop/Cursor 可直接接；强迫自己梳理只读能力/资源/提示；验证 MCP 协议而不是只看文档。
- 口语化：“自建一遍才知道 tools/resources/prompts 的边界，也才能讲清 Client 桥的取舍。”

### E. 网络 / 运维（6 题）

**E1. 告警风暴怎么处理？**
- 要点：同类告警 dedup_key 去重；根因分组（link_down > device_unreachable > device_offline > host_down）；下游 BFS 抑制；抑制只影响展示层不删 active；通知按级别/去重节流。
- 口语化：“风暴的核心不是‘告警太多’，而是‘分不清谁是根因’，所以我先做根因聚合再做抑制展示。”

**E2. 根因抑制是什么？**
- 要点：链路/设备级根因下游告警标 `suppressed_by`；成员仍在 active、可展开；处理根因后整组恢复；不是“删告警”。
- 口语化：“抑制是排序和降噪，不是掩盖数据，审计/原始告警都还在。”

**E3. NC 有什么局限？怎么补？**
- 要点：告警清除滞后 >3 分钟、时钟漂移约 10 分钟、接口计数缺失、拓扑只含已纳管；后端做恢复判定 + `stale_source`、`observed_at`/`source_ts` 双时间基准、指标仿真标注、拓扑补全。
- 口语化：“我没有假设 NC 是完美数据源，而是把它的滞后和时钟差当成一等公民处理。”

**E4. 路径追踪怎么补全？**
- 要点：NC flow-analysis 拿真实 hop；拓扑 BFS 补全/推断；返回 complete/partial/failed 和断点；simulator 驱动明确返回不支持，不伪造。
- 口语化：“路径追踪的底线是‘不编 hop’，拿不到就说拿不到，并给 traceroute/路由表交叉验证建议。”

**E5. 故障注入实验怎么做的？**
- 要点：20 个排障场景，覆盖主机离线、设备不可达、链路中断、端口 shutdown、路由缺失、VLAN 错配、广播风暴、高 CPU、带宽；fixture 确定性注入；38 场景双引擎跑。
- 口语化：“我用场景化故障注入把‘演示’变成‘可回归’，每次改动都能跑同一套评测。”

**E6. 告警恢复判定为什么要自建？**
- 要点：NC 清除滞后，直接用 NC 状态会“假活跃”；后端按数据源实际状态（ping/可达性）判恢复，保留 stale_source 标记；软删除+审计保留追溯。
- 口语化：“用户看到的‘还没清’有时只是 NC 慢，我要把‘真实恢复’和‘展示滞后’分开。”

### F. 工程 / 后端（6 题）

**F1. 为什么 FastAPI + asyncio？**
- 要点：Python AI 生态一致；异步适合采集/HTTP/SSE；Pydantic 校验/OpenAPI 自带；单人项目开发效率高。
- 口语化：“技术选型先看团队和场景，我这个场景就是 Python + 异步 + 快速迭代。”

**F2. 为什么不用 Spring / MySQL？**
- 要点：范围是单机演示/个人项目；SQLite WAL 零运维、足够；Spring 重；如果生产多实例，会换 PostgreSQL + 迁移/消息队列。不是“不会”，是权衡。
- 口语化：“选 SQLite 不是因为它更强，而是它让这个阶段的问题更少；扩展到生产我会换 PostgreSQL。”

**F3. 采集稳定性怎么保证？**
- 要点：5 秒轮询；超时/异常隔离；单设备失败不影响整体；采集状态/健康度暴露；恢复判定与 stale_source；日志/审计；测试覆盖 normalize/pipeline。
- 口语化：“采集是 Agent 的地基，我的原则是‘单个设备坏不能拖垮全局’。”

**F4. 数据库怎么设计的？**
- 要点：设备/主机/链路/告警/指标/审计/场景等表；WAL；去重键；软删除字段；时间双基准；状态机字段（open/cleared/silenced）；索引按查询。
- 口语化：“设计围绕‘可追溯’：告警生命周期、审计、软删除、双时间都落库，Agent 才能引用证据。”

**F5. 测试策略是什么？**
- 要点：后端 171（检测/normalize/pipeline/告警/路径/通知/stale replay）；Agent 256（工具/路由/图/SSE/RAG/MCP/评测）；MCP Server 30；Bridge 10；fixture 离线确定性；评测双引擎。
- 口语化：“我不追求覆盖率数字，而是按‘最容易坏的边界’写测试：工具失败、截断、路由、恢复、断开。”

**F6. 怎么部署？扩展真实设备呢？**
- 要点：当前 Windows 单机演示（uvicorn + 前端 build + MCP 进程）；生产建议 Docker/systemd/Nginx、认证鉴权、密钥管理、监控告警；真实设备接 SNMP/Netconf/厂商 API，替换 collector/driver。
- 口语化：“这个项目已经预留 driver 抽象，扩展真实设备主要是换采集器，不改 Agent 契约。”

**F7. 前端怎么和 Agent 联调？**
- 要点：契约先行（/api/chat 与 /api/chat/stream 事件表）；前端 mock 与真实后端切换；headless Edge 冒烟覆盖关键页面；流式/引用/action 卡片都有状态。
- 口语化：“前后端联调我不靠‘口头对齐’，先把事件契约写死，再各自按契约开发。”

### G. AI 岗通用（8 题）

**G1. 怎么防幻觉？**
- 要点：工具/知识库为唯一事实源；无命中明确说无；工具失败不编；引用可追溯；写操作必须确认；评测专门有无命中场景。
- 口语化：“我把幻觉当成产品问题不是模型问题，靠约束、证据和评测一起压。”

**G2. 评测怎么做？**
- 要点：38 场景（20 排障 + 10 多 Agent + 5 只读 + 3 RAG）；指标根因/设备/证据/动作正确率/自动执行违规；mock 离线可回归；双引擎对照。
- 口语化：“评测不是跑分，是回归网：每次改路由/工具/RAG 都要跑同一套。”

**G3. prompt 怎么设计？**
- 要点：系统提示明确角色/边界/工具使用/引用规则；RAG 上下文要求 [K1]；诊断限制步数；不许编造；工具 schema 清晰。
- 口语化：“我的 prompt 不是‘你是一个专家’，而是把输出约束和失败处理写清楚。”

**G4. 多轮记忆怎么做的？**
- 要点：conversation 表存历史；LangGraph checkpointer thread_id=conversation_id 恢复图状态；最近 8 条注入；会话详情可查；删除会话有 action 确认。
- 口语化：“记忆分两层：对话内容在业务表，图状态在 checkpointer，两者用同一个 conversation_id 串起来。”

**G5. 模型怎么切换？**
- 要点：provider 抽象（DeepSeek/OpenAI/Ollama/OpenAI 兼容/mock）；改环境变量即可；真实模型用 ChatOpenAI，mock 走规则；trace 记录 provider/model，不泄露 key。
- 口语化：“我不把模型写死，模型是配置不是架构。”

**G6. 成本/延迟怎么权衡？**
- 要点：RAG top5、诊断 max_steps=6、plan≤3、流式不二次生成、polish 可关；离线 mock 用于 CI；真实模型抽测。
- 口语化：“先保证路径短，再谈模型便宜；大部分延迟来自多步工具循环，不是 token 本身。”

**G7. 上线风险有哪些？**
- 要点：模型不确定、权限/审计、数据一致、MCP 外部进程、并发/重试、成本；缓解：规则路由、人工确认、TTL/CAS、只读边界、超时/降级、评测。
- 口语化：“我不认为它明天就能接管生产，风险清单要跟用户一起定，先做‘辅助决策’而不是自动执行。”

**G8. 如果重做，会改什么？**
- 要点：更早做可观测/评测；路由从第一天规则+LLM 双轨；RAG 先评估再上；MCP 别和主 Agent 版本绑；前端更早接契约 mock。
- 口语化：“重做我会把‘可回归’提前，而不是功能做完再补测试。”

**G9. 什么时候不该用大模型？**
- 要点：强确定性/强事务场景（写配置、计费、权限）用规则/状态机更稳；大模型适合“理解意图、解释、归纳、辅助决策”；我的写操作就是规则路由 + 人工确认。
- 口语化：“大模型不是万能胶，能不用它的地方我尽量不用，比如动作执行。”

### I. 飞书机器人接入（2 题）

**Q1：为什么做飞书机器人？和 Webhook 告警通知什么区别？**
要点：Webhook 是**单向**（告警推到群）；机器人是**双向**（群里问一句，机器人调 Agent 查真实网络数据再回答）。接入用飞书开放平台自建应用 + **长连接事件订阅**，不需要公网 IP/内网穿透，本地就能跑——这是选长连接的核心理由（开发调试成本低、事件延迟低）。

**Q2：机器人和 AI 的写操作安全怎么保证？**
要点：机器人**不执行任何写操作**。用户在飞书说「清空告警」时，只返回「待确认」提示（含确认文案），执行必须到 Web 大屏点确认——与 Agent 的 `interrupt()` 人机中断保持一致。另外有群/用户白名单、每群每分钟限流、message_id 去重（飞书 3 秒超时会重推）、凭证只从 `.env` 读取不入库。

## 五、压力问题 / 质疑应对（先承认，再给证据）

**Q1. “是不是套壳？”**
- 回答：不是只接 API。项目有完整数据链路（NC→后端→检测/告警）、Agent 编排（图/工具/路由/确认）、MCP 双向、评测与测试；可现场看 trace/tool_sequence/评测报告。
- 口语化：“套壳只能回答‘像’，我这个项目要能回答‘依据哪条数据、能不能确认执行’。”

**Q2. “一个人做的？”**
- 回答：是个人项目、独立开发；范围可控才敢做全栈。用了官方 SDK/开源库，但架构、数据模型、路由、评测、交互都是自己决策。
- 口语化：“独立开发不等于闭门造车，我更多是站在官方 SDK 上做工程取舍。”

**Q3. “模拟器算真实吗？”**
- 回答：PT/NC 是真实控制器 API 和真实采集链路，但不是生产流量；价值在于验证链路和 Agent 工程，不宣称生产准确性；生产要接真实设备/SNMP。
- 口语化：“我不会说它是生产网络，但它是真实的采集—检测—Agent 闭环，仿真只体现在设备和时钟。”

**Q4. “100% 是不是过拟合？”**
- 回答：100% 是 mock/确定性评测集的回归基线，不是生产指标；真实 LLM 用同一套场景对照，且动作安全门/自动执行违规独立校验；场景是设计过的。
- 口语化：“100% 我只敢说是‘这套场景 100%’，不是‘线上 100%’，面试里我会把边界说清。”

**Q5. “为什么不用 AgentExecutor / Dify / Coze / LlamaIndex？”**
- 回答：需要显式图、Send 并行、interrupt、checkpoint、细 trace；低代码平台控制力不够；LlamaIndex 对 18 块 RAG 太重。选型服务目标，不是追新。
- 口语化：“我不是排斥框架，是这些东西解决不了‘每一步可控、可恢复’。”

**Q6. “代码是 AI 写的吧？”**
- 回答：AI 是工具，架构/取舍/调试是我做的；可以现场改一个路由规则/加一个测试，讲清为什么；评测和 trace 是证据。
- 口语化：“AI 可以帮我写代码，但没法替我决定‘写操作该不该自动执行’。”

**Q7. “生产能落地吗？”**
- 回答：当前是演示/个人项目；生产要补权限、HA、密钥、审计合规、可观测、并发、数据治理；但当前设计预留了 driver/engine/provider/MCP 边界。
- 口语化：“我会明确说它是‘可演示的原型’，不是‘已上线的生产系统’。”

## 六、不会的问题怎么答（诚实 + 迁移 + 学习路径）

**公式**：承认不会 → 说相邻经验/可迁移点 → 给学习/验证路径 → 不编结论。

- 例 1（分布式 checkpointer）：“我目前用的是 SqliteSaver 单机方案，没在生产多实例跑过；但我知道要把 thread 状态放 PostgreSQL/Redis，关键是并发写和恢复一致性。给我一周我会先做多实例压力测试再定。”
