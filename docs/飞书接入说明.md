# 飞书接入说明（告警 / 恢复通知 + 双向机器人）

> 本文说明 Campus Twin 数字孪生运维平台如何把**告警 / 恢复通知**推到飞书群，以及
> “群自定义机器人 Webhook（单向通知）”和“双向飞书机器人（事件订阅）”两套接入方式的区别。
>
> - 通知实现：`backend/app/notify.py`（W15：飞书 interactive 富卡片 + 恢复通知 + 运行时配置）
> - 本地实测样例：`logs/feishu_card_sample.json`（告警卡片）、`logs/feishu_recovery_card_sample.json`（恢复卡片）
> - 双向机器人：`feishu-bot/`（Node.js + 飞书官方 SDK，见 `feishu-bot/README.md`）

---

## 一、两套飞书接入方式（先选型）

| 能力 | **群自定义机器人 Webhook**（本文重点） | **双向飞书机器人**（`feishu-bot/`） |
|---|---|---|
| 方向 | **单向**：平台 → 飞书群（只推告警/恢复） | **双向**：群里发消息，机器人查真实数据并回答 |
| 接入凭证 | 群机器人 Webhook URL（一个字符串即可） | 飞书开放平台企业自建应用 **App ID / App Secret** |
| 是否需要公网 | 不需要（后端主动出站 HTTPS 请求） | 不需要（长连接 WebSocket 出站） |
| 典型用途 | 故障告警、恢复通知、值班群推送 | 在飞书里问 AI / 查状态 / 查告警 / 路径追踪 |
| 配置位置 | 环境变量或运行时 API（本版新增） | `feishu-bot/.env` |
| 文档 | 本文 | `feishu-bot/README.md`、`docs/飞书机器人接入.md` |

> 两者可以同时使用：Webhook 负责“故障来了主动喊你”，双向机器人负责“你想查的时候问它”。
> **告警推送只需要本文第一～六节**，不需要创建飞书应用。

## 二、获取群自定义机器人 Webhook URL（3 步）

在 macOS / Windows 飞书客户端里：

1. **进入目标群 → 群设置**
   点群名称右侧「…」→「设置」→ 找到「群机器人」。
2. **添加机器人 → 自定义机器人**
   点「添加机器人」→ 选择「**自定义机器人**」→ 填名称（建议「Campus Twin 告警」）、
   可选头像 → 点「添加」。
3. **复制 Webhook 地址**
   添加完成后页面会显示形如
   `https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`
   的地址，复制它（这就是后端要配置的 `NOTIFY_WEBHOOK_URL`）。

**安全设置（添加时可选项）**：

| 选项 | 演示建议 | 说明 |
|---|---|---|
| 自定义关键词 | 可留空 | 消息必须包含关键词才会推送；留空最省事 |
| IP 白名单 | 可留空 | 需要知道后端主机**出站公网 IP**；本机演示通常不填 |
| 签名校验 | **留空**（本版未实现签名头，开启后会返回 `19021`） | 若必须开启，见第八节“签名校验扩展点” |

> ⚠️ 该 Webhook URL 等同于群内发消息的凭证：**不要提交到 Git、不要截图外发**。
> 本仓库 `.env` 类文件均被 `.gitignore` 忽略，`GET /api/notify/status` 也只返回打码后的 URL。

## 三、后端配置

### 3.1 环境变量（推荐 `.env` / 启动脚本注入）

W15 新增 2 个变量（其余沿用 W10）：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `NOTIFY_ENABLED` | `false` | 通知总开关；需同时配置 URL 才会真正启用 |
| `NOTIFY_WEBHOOK_URL` | 空 | 群自定义机器人 Webhook URL（第二节复制的那串） |
| `NOTIFY_WEBHOOK_TYPE` | `generic` | `generic` / `dingtalk` / `feishu` / `wecom`；**飞书选 `feishu`** |
| `NOTIFY_MIN_SEVERITY` | `critical` | 最低推送级别：`critical` 或 `warning`（info 类事件不推） |
| `NOTIFY_ON_RECOVERY` | `true` | **W15 新增**：告警恢复（cleared）时推绿色恢复卡片 |
| `NOTIFY_LINK_URL` | 空 | **W15 新增**：卡片底部按钮「打开 3D 大屏」的跳转地址；空=不显示按钮 |
| `NOTIFY_DEDUP_SECONDS` | `300` | 同 dedup_key 去重窗口（5 分钟） |
| `NOTIFY_TIMEOUT` | `5` | 单次 HTTP 超时（秒） |
| `NOTIFY_RETRY_DELAY_1` / `_2` | `1` / `3` | 失败重试退避（共重试 2 次） |

**飞书演示配置示例**（PowerShell，写入启动脚本或 `.env`）：

```powershell
$env:NO_PROXY = '*'                       # 本机 127.0.0.1 接收器不能走系统代理
$env:no_proxy = '*'
$env:NOTIFY_ENABLED = 'true'
$env:NOTIFY_WEBHOOK_URL = 'https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx'
$env:NOTIFY_WEBHOOK_TYPE = 'feishu'
$env:NOTIFY_MIN_SEVERITY = 'warning'
$env:NOTIFY_ON_RECOVERY = 'true'
$env:NOTIFY_LINK_URL = 'http://127.0.0.1:5173/'   # 3D 大屏；外网演示时换成可访问地址
```

`.env` 形式：

```dotenv
NOTIFY_ENABLED=true
NOTIFY_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
NOTIFY_WEBHOOK_TYPE=feishu
NOTIFY_MIN_SEVERITY=warning
NOTIFY_ON_RECOVERY=true
NOTIFY_LINK_URL=http://127.0.0.1:5173/
```

> 修改环境变量后需要**重启后端**（:8000）生效；
> 不想重启时用下一节的运行时配置接口（已实现：`NotifyService.apply_config` +
> `POST /api/notify/config`，并持久化到 `backend/data/notify_config.json`）。
>
> 注意：`tools/demo_start.ps1` 为了本机自测注入的是 **generic + 127.0.0.1:9000 本地接收器**；
> 做**真实飞书演示**时把其中的 `NOTIFY_WEBHOOK_TYPE` 改成 `feishu`、`NOTIFY_WEBHOOK_URL`
> 换成真实群地址（并加 `NOTIFY_LINK_URL`）后重启后端，或启动后端后用
> `POST /api/notify/config` 在线切换（无需改脚本/重启）。

### 3.2 运行时配置（不重启后端，供 API / UI 调用）

后端已提供 `POST /api/notify/config`（`backend/app/main.py`，W15）：

```text
POST /api/notify/config
  body:  {enabled?: bool, webhook_url?: str, webhook_type?: "generic|dingtalk|feishu|wecom",
          min_severity?: "critical|warning", on_recovery?: bool}
          # 所有字段可选，只提交要改的项
  200:   {ok: true, persisted: true, config_file: "notify_config.json", status: <status()>}
  400:   {detail: "webhook_url 必须是合法的 http:// 或 https:// 地址"} 等中文错误
  500:   {detail: "通知配置已运行时生效，但持久化失败：..."}

GET /api/notify/status   # 实时反映；status.webhook_url 已打码，不泄露 token
```

行为要点：

- **校验**：URL 必须为非空 http(s)、type/severity 必须在白名单内，否则 400（不改任何状态）；
- **运行时生效**：调用 `notify.apply_config(...)`，连接类配置（enabled / url / type）变化时
  **重建 httpx client 与后台 worker**，新配置立即生效，无需重启；
- **持久化**：写入 `backend/data/notify_config.json`（已 gitignore，权限尽量 600）；
  后端重启时 lifespan 自动加载该文件覆盖 env 配置（`status().config_source="file"`）；
- **恢复默认**：环境变量初始配置保留在 `status()["env_defaults"]`，UI 可据此回填；
- **本地接收器自测**：把 `webhook_url` 指向 `http://127.0.0.1:9000/webhook` 即可，不打扰真实群。

`POST /api/notify/test`（已有）发送告警测试卡片；如需“恢复测试卡片”，
`NotifyService.send_test(kind="recovery")` 已实现（main.py 尚未暴露 `kind` 参数，
Lead 可按需在端点上加可选 body `{"kind": "test|recovery"}`）。

直接调用服务层（不经 HTTP / 供脚本使用）：

```python
await notify.apply_config(
    enabled=True,                    # 不传 = 保持当前值
    webhook_url="https://open.feishu.cn/open-apis/bot/v2/hook/...",
    webhook_type="feishu",           # generic|dingtalk|feishu|wecom，非法抛 NotifyConfigError
    min_severity="warning",          # critical|warning|info，非法抛 NotifyConfigError
    notify_on_recovery=True,
    link_url="http://127.0.0.1:5173/",   # 卡片按钮，API 暂未暴露（env 支持）
)
```

`GET /api/notify/status` 在 W10 字段基础上新增：

| 字段 | 说明 |
|---|---|
| `on_recovery` | 恢复通知是否开启（对应 `NOTIFY_ON_RECOVERY`） |
| `last_payload_kind` | 最近一次构造的消息种类：`alert` / `recovery` / `test` |
| `link_url` / `link_button` | 卡片按钮地址 / 是否显示按钮 |
| `card_type` | `feishu_interactive`（飞书卡片）或 `null`（其它类型） |
| `enabled_requested` | 开关意图（区别于 `enabled`=开关且已配 URL） |
| `config_source` | `env`（环境变量）/ `runtime`（API 覆盖）/ `file`（启动加载持久化文件） |
| `available_types` / `env_defaults` / `max_recovery_cards_per_batch` | UI 可选类型 / 初始默认值 / 批量恢复聚合阈值 |

## 四、飞书卡片长什么样

### 4.1 告警卡片（红色 header）

`NOTIFY_WEBHOOK_TYPE=feishu` 时，每条新 active 告警（severity ≥ `NOTIFY_MIN_SEVERITY`）
会收到一张 **interactive 卡片**：

```json
{
  "msg_type": "interactive",
  "card": {
    "config": {"wide_screen_mode": true},
    "header": {
      "title": {"tag": "plain_text", "content": "【告警】主机离线：PC-JX1"},
      "template": "red"
    },
    "elements": [
      {"tag": "div", "fields": [
        {"is_short": true,  "text": {"tag": "lark_md", "content": "**级别**\ncritical"}},
        {"is_short": true,  "text": {"tag": "lark_md", "content": "**设备**\nPC-JX1"}},
        {"is_short": true,  "text": {"tag": "lark_md", "content": "**规则**\nhost_down"}},
        {"is_short": true,  "text": {"tag": "lark_md", "content": "**时间**\n2026-11-03 16:38:48"}},
        {"is_short": false, "text": {"tag": "lark_md", "content": "**详情**\nNC /host pingStatus=FAILURE；主机 PC-JX1(192.168.20.10) 与网络失联（接入交换机 SW-JX Fa0/1）"}}
      ]},
      {"tag": "hr"},
      {"tag": "note", "elements": [
        {"tag": "plain_text", "content": "Campus Twin 数字孪生运维平台 · 仅通知，请以平台数据为准"}
      ]},
      {"tag": "action", "actions": [
        {"tag": "button", "text": {"tag": "plain_text", "content": "打开 3D 大屏"},
         "type": "primary", "url": "http://127.0.0.1:5173/"}
      ]}
    ]
  }
}
```

字段与颜色的规则：

| 项目 | 规则 |
|---|---|
| header 标题 | 告警 `【告警】<title>`；恢复 `【恢复】<title>`；测试 `【测试】<title>` |
| header 颜色 | critical=`red`、warning=`orange`、info=`blue`、test=`green`、恢复=`green` |
| 字段区（5 项） | 告警：级别 / 设备 / 规则 / 时间 / 详情；恢复：级别 / 设备 / 规则 / 恢复时间 / 恢复原因 |
| 时间 | 用 `observed_at`（**宿主机采集时间**，北京时间 UTC+8），不用 NC 的 `source_ts`（PT 仿真时钟实测差约 10 分钟） |
| 备注行 | 固定“Campus Twin 数字孪生运维平台 · 仅通知，请以平台数据为准” |
| 按钮 | 仅 `NOTIFY_LINK_URL` 非空时出现；文字固定「打开 3D 大屏」 |

> 飞书**自定义机器人**发送的卡片：按钮/文字链接只支持**跳转 URL**，不支持点击回调服务端
> （官方限制，见[自定义机器人使用指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)）。
> 因此这里不做“卡片上确认/处置”的交互，写操作统一在 Web 大屏完成。

### 4.2 恢复卡片（绿色 header）

`NOTIFY_ON_RECOVERY=true` 时，告警 cleared（pipeline 检测到恢复）会推一张绿色恢复卡片：

```json
{
  "msg_type": "interactive",
  "card": {
    "header": {
      "title": {"tag": "plain_text", "content": "【恢复】主机恢复：PC-JX1"},
      "template": "green"
    },
    "elements": [
      {"tag": "div", "fields": [
        {"is_short": true,  "text": {"tag": "lark_md", "content": "**级别**\n已恢复"}},
        {"is_short": true,  "text": {"tag": "lark_md", "content": "**设备**\nPC-JX1"}},
        {"is_short": true,  "text": {"tag": "lark_md", "content": "**规则**\nhost_down"}},
        {"is_short": true,  "text": {"tag": "lark_md", "content": "**恢复时间**\n2026-11-03 16:38:48"}},
        {"is_short": false, "text": {"tag": "lark_md", "content": "**恢复原因**\npingStatus FAILURE -> SUCCESS（按数据源实际状态判定恢复，不等 NC issue 清除）"}}
      ]},
      {"tag": "hr"},
      {"tag": "note", "elements": [
        {"tag": "plain_text", "content": "Campus Twin 数字孪生运维平台 · 仅通知，请以平台数据为准"}
      ]}
    ]
  }
}
```

恢复通知的实现细节（见 `pipeline.py` 的 `_persist_detection` / `notify_recoveries`）：

- 每个 cleared 事件落库后（`state=cleared` + `clear_reason` + `resolved_at`）才投递，
  卡片上的“恢复原因”就是库里的 `clear_reason`，与 `/api/alerts?state=cleared` 数据一致；
- 恢复设备名优先用 hostname（如 `PC-JX1`），不会把 NC 内部 UUID 直接展示给值班群；
- **独立去重命名空间** `recovery:<dedup_key>`（与告警去重互不影响：故障后 5 分钟内恢复，
  恢复卡片照样会发）；
- **批量恢复聚合**：单轮恢复超过 5 条时合并成一张“【恢复】批量恢复：本轮 N 条告警已恢复”卡片，
  避免 NC issue 集中清除（W3 实测曾一次清 11 条）刷屏；
- 失败重试沿用告警的 2 次退避（1s / 3s），不阻塞 5 秒采集循环。

## 五、演示流程（故障 → 告警卡片 → 恢复 → 恢复卡片）

前置：后端加载 W15 代码并以 `NOTIFY_WEBHOOK_TYPE=feishu` + 真实群 Webhook 启动
（或后端在线时调用 `POST /api/notify/config` 切到 feishu，无需重启）。

```text
① 配好飞书：NOTIFY_ENABLED=true、URL、TYPE=feishu、ON_RECOVERY=true、LINK_URL=http://127.0.0.1:5173/
② 打开后端日志确认：Webhook 通知已启用：type=feishu url=... min_severity=warning on_recovery=True
③ 注入故障（Packet Tracer 里对 SW-JX Fa0/1 执行 shutdown；或演示用 simulator 注入）
④ 等 1 个采集轮次（默认 5s）→ 飞书群收到红色【告警】卡片
⑤ 恢复故障（no shutdown）→ 1 个采集轮次内收到绿色【恢复】卡片
⑥ 大屏 /api/alerts 里同一条告警从 active → cleared，与恢复卡片时间一致
```

排查用命令：

```powershell
# 1) 本地接收器自测（不打扰真实群）：起接收器后把 NOTIFY_WEBHOOK_URL 指到它
D:\zdsh\campus-twin\.venv\Scripts\python.exe tools\webhook_receiver.py   # 127.0.0.1:9000
# 日志：logs/webhook.log

# 2) 查看当前通知配置/发送状态（打码后的 URL、sent_count、last_error、last_payload_kind）
Invoke-RestMethod http://127.0.0.1:8000/api/notify/status

# 3) 在线配置（不重启）：切换到飞书 + 填 Webhook URL + 开启恢复通知
Invoke-RestMethod -Method Post http://127.0.0.1:8000/api/notify/config -ContentType 'application/json' -Body (@{
  enabled = $true
  webhook_url = 'https://open.feishu.cn/open-apis/bot/v2/hook/xxxx'
  webhook_type = 'feishu'
  min_severity = 'warning'
  on_recovery = $true
} | ConvertTo-Json)

# 4) 发测试消息（飞书群应收到卡片）
Invoke-RestMethod -Method Post http://127.0.0.1:8000/api/notify/test
```

> 注意：系统代理（如 Clash 127.0.0.1:7897）会拦截本机 HTTP，演示前设 `NO_PROXY='*'`；
> `NotifyService` 内部 httpx 已使用 `trust_env=False`，但启动脚本/curl 仍需绕过代理。

## 六、常见错误码与排查

飞书自定义机器人**即使拒绝消息也常返回 HTTP 200**，真正结果在响应体 `code` 字段。
本后端（`notify.py::_post`）会解析 `code`/`errcode`/`StatusCode`，**非 0 视为失败并按 1s/3s 重试**，
错误写入 `GET /api/notify/status` 的 `last_error` 与后端日志。

| code / 现象 | 含义 | 排查 / 解决 |
|---|---|---|
| `19001` | invalid param：请求体参数不合法（卡片 JSON 结构/字段错误） | 对照 `logs/feishu_card_sample.json` 检查 `msg_type`/`card`/`elements` 结构；不要混用 `msg_type` 与 `msgtype` |
| `19002` | `params error, msg_type need`：结构与 `msg_type` 不匹配（如把 text 结构发给卡片、缺 `msg_type`） | 飞书必须是 `{"msg_type":"interactive","card":{...}}`；检查是否误用了钉钉/企微格式 |
| `19021` | `sign match fail or timestamp is not within one hour from current time`：开启了**签名校验** | 演示：自定义机器人安全设置里**留空/关闭**或改 IP 白名单；生产：按第八节实现 `timestamp + sign` |
| `19021`（另一种） | 时间戳过期（与服务器时间偏差 >1 小时） | 校准服务器时间 |
| `9499` | `bad request / invalid param`（v1 消息接口参数错误） | 检查 URL、JSON 字段拼写、消息体大小 |
| HTTP `429` | 触发频控（群机器人 Webhook 上限约 **100 次/分钟**） | 降低告警频率（调高 `NOTIFY_MIN_SEVERITY`、依赖 5 分钟去重），或拆分到多个群机器人 |
| 发送成功但群里没消息 | 机器人被移出群 / 群已解散 / URL 属于别的群 | 群设置 → 群机器人 确认机器人仍在，重新复制 URL |
| `last_error` 含 `ProxyError` / 连接超时 | 系统代理拦截 | 启动脚本设 `NO_PROXY='*'`、`no_proxy='*'`；确认后端进程环境变量生效 |
| `last_error` 含 `HTTP 404` | URL 复制不完整/写错 | 重新复制完整 `https://open.feishu.cn/open-apis/bot/v2/hook/...` |
| 卡片显示 `unknown content value` 等结构报错 | 卡片字段不合法（如 `fields` 里的 `text` 缺 `tag`） | 用 `logs/feishu_card_sample.json` 比对；改完跑 `pytest backend/tests/test_notify_feishu.py` |

## 七、双向飞书机器人（事件订阅）是另一套

如果你希望“**在飞书群里直接问**：状态怎么样 / 哪个设备掉线了 / 路径 PC-JX1 到 Server-1”，
那是**双向机器人**，与本文的 Webhook 通知不是一回事：

- 需要在[飞书开放平台](https://open.feishu.cn/app)创建**企业自建应用**，拿 **App ID / App Secret**；
- 开启「机器人」能力、申请 `im:message` / `im:message:send_as_bot` 权限；
- 事件订阅选**长连接**（无需公网 IP）、订阅 `im.message.receive_v1`；
- 本地启动：`cd feishu-bot && copy .env.example .env`（填凭证）→ `npm start`；
- 代码/步骤/自测：见 `feishu-bot/README.md` 与 `docs/飞书机器人接入.md`。

| 维度 | Webhook 通知（本文） | 双向机器人（`feishu-bot/`） |
|---|---|---|
| 凭证 | 群机器人 URL | App ID + App Secret |
| 方向 | 平台 → 群 | 群 ⇄ 平台（可问答） |
| 推送内容 | 告警/恢复卡片 | 自然语言回答 + 卡片提示 |
| 是否需要开放平台应用 | 否 | 是 |
| 写操作 | 不涉及 | 只生成“待确认”，需 Web 大屏人工确认 |

## 八、安全与扩展

- **凭证隔离**：Webhook URL 只从环境变量读取，不写入代码/文档示例中的真实值；
  `status()` 返回的 URL 已打码；`.env` 类文件不进版本库。
- **只通知不执行**：告警/恢复卡片只做信息推送，卡片按钮只跳转 3D 大屏，
  不提供“在飞书里删告警/改配置”的回调入口（自定义机器人本身也不支持回调）。
- **发送不阻塞**：入队 + 后台 worker，单条失败重试 2 次（1s/3s），绝不影响 5s 采集循环。
- **签名校验扩展点（本版未实现）**：若企业要求开启签名校验，在
  `backend/app/notify.py::_post` 构造 body 时追加 `timestamp` 与 `sign`：

  ```python
  import base64, hashlib, hmac, time

  def _feishu_sign(secret: str) -> dict:
      timestamp = str(int(time.time()))
      string_to_sign = "{}\n{}".format(timestamp, secret)
      digest = hmac.new(string_to_sign.encode("utf-8"), digestmod=hashlib.sha256).digest()
      return {"timestamp": timestamp, "sign": base64.b64encode(digest).decode("utf-8")}
  ```

  即把 `{"msg_type": ..., "card": ...}` 扩展为
  `{"timestamp": ts, "sign": sign, "msg_type": ..., "card": ...}`，
  secret 建议放 `NOTIFY_WEBHOOK_SECRET` 环境变量（不落库）。
