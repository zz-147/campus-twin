# 飞书机器人接入说明（W14）

> 在飞书里直接问 AI / 查校园网络状态。长连接模式，**不需要公网 IP、不需要内网穿透**，本地启动即可。
> 代码目录：[`feishu-bot/`](../feishu-bot/)（Node.js + 飞书官方 SDK）。

## 一、与「Webhook 告警通知」的区别

| 能力 | Webhook 通知（W10，已有） | 飞书机器人（W14，本功能） |
|---|---|---|
| 方向 | **单向**：告警推到群 | **双向**：群里发消息，机器人调 Agent 回答 |
| 接入方式 | 群自定义机器人 webhook URL | 飞书开放平台自建应用 + 长连接事件订阅 |
| 是否需要公网 | 否（出站请求） | 否（长连接，出站 WebSocket） |
| 能问 AI 吗 | ❌ 只能被动接收告警 | ✅ 状态 / 告警 / 路径 / 读文件 / 任意问题 |

## 二、架构

```
飞书用户（群/私聊）
   │ 消息事件（长连接 WebSocket，出站）
   ▼
feishu-bot（Node.js）
   ├─ 指令路由：状态 / 告警 / 路径 / 读文件 / 写操作识别
   ├─ 安全：群/用户白名单、限流、消息去重、写操作不执行
   └─ HTTP POST /api/chat
        ▼
AI Agent :8100（LangGraph 多 Agent · 23 工具 · RAG · SSE）
        ▼
后端 :8000（真实 NC 数据）/ MCP Bridge :8200（filesystem/memory）
```

## 三、配置步骤

1. 飞书开放平台创建**企业自建应用** → 开启**机器人**能力
2. 权限：`im:message`、`im:message:send_as_bot`
3. 事件订阅：选择**长连接**，订阅 `im.message.receive_v1`
4. 复制 App ID / App Secret → 写入 `feishu-bot/.env`（**不要提交仓库**）
5. `npm install && npm start`，看到「长连接已启动」后在飞书发消息

完整步骤与命令见 [feishu-bot/README.md](../feishu-bot/README.md)。

## 四、指令示例

| 飞书消息 | 机器人行为 |
|---|---|
| `状态` | 返回整体网络健康度（真实 NC 数据） |
| `告警` | 返回告警 + 根因分组 |
| `路径 PC-JX1 到 Server-1` | 调真实 flow-analysis 返回 4 跳路径 |
| `读 configs/core-3650.txt` | 通过 MCP filesystem 读取真实配置 |
| `帮助` | 指令菜单 |
| `清空已恢复的告警` | **只返回待确认提示**，需到 Web 大屏确认后才执行 |

## 五、安全设计（面试可讲）

- **凭证隔离**：飞书 App ID/Secret 只从 `.env`/环境变量读取，`.env` 在 `.gitignore`；代码中无硬编码
- **白名单 + 限流**：群/用户白名单、每群每分钟请求上限
- **写操作不落地**：机器人不执行任何写操作，只生成「待确认」提示；执行必须人工在 Web 端确认（与 Agent 的 `interrupt()` 人机中断一致）
- **消息去重**：飞书 3 秒超时重推时，同一 message_id 只处理一次
- **优雅降级**：Agent 不可用时回复明确错误，不崩溃、不编造

## 七、面试讲点 / 简历写法

> **飞书机器人双向接入**：基于飞书开放平台自建应用 + 长连接事件订阅（无需公网），实现群内自然语言问答——指令路由（状态/告警/路径/读配置）、Agent 多轮会话、写操作「只提示不执行」的人机协同；配套群/用户白名单、限流、消息去重与优雅降级，19 项离线自测通过。

可延伸讨论：
- 为什么用长连接而不是 Webhook：本地无公网、开发调试快、事件延迟低
- 为什么机器人不执行写操作：与 Web 端 `interrupt()` 人机确认保持一致，避免"群里一句话就把生产告警删了"
- 如何扩展到企业微信/钉钉：企业微信需公网回调（加密验签），本项目的 Webhook 通知已支持单向；双向需按各平台应用协议适配
