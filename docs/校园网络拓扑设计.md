# 校园网络拓扑设计（W1：在 PT 里搭出可被 NC 管理的校园网）

> 目标：用 5 台 Cisco 网络设备 + 5 台终端 + Network Controller，搭出一个
> **三层架构、可被 NC 完整发现、可注入故障**的校园网络，作为数字孪生平台的真实数据源。

## 一、验收标准

搭好并完成 NC 发现后，跑探针应该看到：

- `network-device/count` ≥ 5，且 5 台设备的 `collectionStatus` 都是 **Managed**
- `topology/physical-topology` 的 `nodes` ≥ 5，`links` ≥ 4
- `host` ≥ 5（PC + Server）
- `network-health` 的 `numUnreachable` = 0

## 六、操作步骤

### 1. 拖设备、连线
按上表拖出设备并连线。NC 在 **End Devices** 分类里。

### 2. 粘贴配置
每台设备的 CLI 配置在 `configs/` 目录：

| 设备 | 配置文件 |
|---|---|
| Core-3560 | [configs/core-3560.txt](../configs/core-3560.txt) |
| SW-JX-2960 | [configs/sw-jx-2960.txt](../configs/sw-jx-2960.txt) |
| SW-SX-2960 | [configs/sw-sx-2960.txt](../configs/sw-sx-2960.txt) |
| SW-SS-2960 | [configs/sw-ss-2960.txt](../configs/sw-ss-2960.txt) |
| Router-2911 | [configs/router-2911.txt](../configs/router-2911.txt) |

操作：点设备 → **CLI** 标签 → 按 Enter → `enable` → `configure terminal` →
把配置文件内容粘贴进去（PT 的 CLI 里右键 → Paste，或 Ctrl+V）→ `end` → `write memory`。

> 3560 生成 RSA 密钥时如果卡在 `[1024]` 提示，按回车即可。

### 3. 配置终端 IP（GUI）
每台 PC/Server → **Config → FastEthernet0 → IP Configuration**：

| 设备 | IP | 掩码 | 网关 |
|---|---|---|---|
| PC-JX1 | 192.168.20.10 | 255.255.255.0 | 192.168.20.1 |
| PC-JX2 | 192.168.20.11 | 255.255.255.0 | 192.168.20.1 |
| PC-SX1 | 192.168.30.10 | 255.255.255.0 | 192.168.30.1 |
| PC-SS1 | 192.168.40.10 | 255.255.255.0 | 192.168.40.1 |
| PC-SS2 | 192.168.40.11 | 255.255.255.0 | 192.168.40.1 |
| Server-1 | 192.168.50.10 | 255.255.255.0 | 192.168.50.1 |

### 4. 配置 NC 设备
点 NC → **Config → Global Settings → Interface Settings**：
- IP: `192.168.10.100`，掩码 `255.255.255.0`，网关 `192.168.10.1`
- 连接的口选第一个以太网接口，接到 Core Fa0/4

### 5. 连通性自检
在 Core-3560 的 CLI 里：

```
ping 192.168.10.11
ping 192.168.10.12
ping 192.168.10.13
ping 10.0.0.2
ping 192.168.20.10
```

全部通再继续。

### 6. NC 发现设备
在 NC 的 Dashboard（用 PT 里的 PC 浏览器访问 NC 的 IP，或双击 NC 打开管理界面）：

**Provisioning → Discovery → Add New Discovery**：
- Discovery Name: `campus`
- Discovery Type: **CDP**
- Seed IP: `192.168.10.1`（核心交换机管理 IP）
- CDP Level: `2`
- Global Credentials: `admin / cisco`
- 等 Discovery Condition 变成 **Complete**

发现完成后，`Assurance → Topology` 应该能看到 5 台网络设备 + 终端。

## 八、故障注入场景（闭环演示用）

搭好网络后，每次只做一个，观察系统是否联动：

| # | 故障 | 操作 | 预期 |
|---|---|---|---|
| 1 | 接入端口宕机 | SW-SS Fa0/1 `shutdown` | NC 发现设备不可达/健康下降，系统告警"宿舍楼终端离线" |
| 2 | 交换机失联 | 拔掉 Core Fa0/2 链路 | 实训楼整段离线，拓扑断链 |
| 3 | 路由缺失 | Router 删掉 `default-information originate` | 跨网段中断，路径追踪断点 |
| 4 | VLAN 错误 | SW-JX Fa0/1 改 VLAN 30 | 教学楼终端拿不到正确网关，主机掉线 |
| 5 | 环路 | SW-JX Fa0/2 与 SW-JX Fa0/3 互连 | 广播风暴、健康问题 |
| 6 | 设备宕机 | Core `reload`（或改错 enable secret） | 大面积不可达，管理面失联 |

> 故障注入后等 30–60 秒（NC 周期采集），再看系统侧告警。

## 关键经验（写文档 / 面试可用）

1. **PT 9 的 NC 只纳管新平台**：2960（IOS 15）、3650（IOS-XE 16.x）、ISR4300 系列可管理；
   3560（IOS 12.2）、2911（IOS 15.1 M4）显示 `Unsupported`。
2. **NC 必须配置默认网关**才能跨网段纳管设备（同网段设备无需网关即可纳管）。
3. **终端（host）发现依赖网络设备侧信息**，核心纳管后 6 台终端全部自动发现。
4. **NC 拓扑只包含已纳管网元**，链路来自邻接关系；核心未纳管时 links=0。
