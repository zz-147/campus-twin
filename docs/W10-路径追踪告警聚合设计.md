## 一、路径追踪（后端 + Agent + 前端）

### 后端 API
```
POST /api/path-trace
body: {"source_ip": "192.168.20.10", "dest_ip": "192.168.50.10"}
→ 200 {
  "ok": true,
  "source_ip": "...", "dest_ip": "...",
  "trace_status": "complete|partial|failed",
  "hops": [
    {"index":0,"device_name":"PC-JX1","device_id":"...","ingress_port":null,"egress_port":"FastEthernet0","role":"source"},
    {"index":1,"device_name":"SW-JX-2960",...},
    ...
    {"index":N,"device_name":"Server-1","role":"destination"}
  ],
  "links": [{"source":"device_id","target":"device_id","link_id":"..."}],
  "elapsed_ms": 1234,
  "error": null
}
```
- 实现：调用 NC `POST /api/v1/flow-analysis {"sourceIP","destIP"}` → `flowAnalysisId`，再轮询 `GET /api/v1/flow-analysis/{id}` 直到完成或 30s 超时；归一化 hop（设备名/端口/角色）。
- 缓存 2 分钟（同 source/dest）；NC 不支持时返回 `ok:false, error` 中文提示。
- 前端链路高亮用 `links` + 现有 topology 坐标。

## 二、告警聚合与根因分组（后端 + 前端）

```
GET /api/alerts/groups?state=active
→ {"count":N, "groups":[
  {"group_id":"g_xxx","root_cause":"link_down","root_device_id":"...","root_device_name":"Core-3650",
   "severity":"critical","title":"Core-3650 ↔ SW-JX 上联中断",
   "alert_ids":[...],"member_count":5,"suppressed_count":12,
   "first_seen":epoch,"last_seen":epoch,
   "members":[{id,alert_type,severity,device_name,detail,suppressed_by}]}]}
```
- 聚合规则：
  1. 同链路/同设备的告警归入一组（root_cause 取最高层级：link_down > device_unreachable > device_offline > host_down）
  2. **抑制**：若根因是 link_down/device_unreachable，其下游主机/设备告警标记 `suppressed_by=group_id`（不删除、不改变 active 状态，只做展示层抑制）
  3. 无根因的独立告警单独成组
- `POST /api/alerts/groups/{group_id}/ack`（可选：整组确认）
- 审计：ack 记录 audit

## 三、Webhook 告警通知（后端）

- 环境变量：`NOTIFY_ENABLED=true|false`、`NOTIFY_WEBHOOK_URL`、`NOTIFY_WEBHOOK_TYPE=generic|dingtalk|feishu|wecom`、`NOTIFY_MIN_SEVERITY=critical|warning`
- 触发时机：新产生 **active 且 severity 达标** 的告警时发送（cleared/info 不发；同一 dedup_key 5 分钟去重）
- 消息格式：通用 JSON `{title,severity,device,time,detail,alert_id}`；钉钉/飞书/企微按各自 markdown 格式包装
- 失败重试 2 次（指数退避 1s/3s），记录 `last_sent_at/last_error`；不阻塞采集主循环（后台任务）
- API：`GET /api/notify/status` → `{enabled,type,min_severity,last_sent_at,last_error,sent_count}`；`POST /api/notify/test` → 发送测试消息

## 四、SNMP 真实设备驱动（后端）

- 新增 `app/collectors/snmp.py`，实现现有 Driver 协议（probe/collect），驱动名 `snmp`，`DRIVER=snmp` 时启用
- 配置：`SNMP_DEVICES=[{"name":"...","ip":"...","community":"public","version":"2c","building":"core"}]`
- 采集指标（MIB-II）：
  - `sysDescr.0`、`sysUpTime.0`、`sysName.0`
  - `ifOperStatus`、`ifInOctets`/`ifOutOctets`（64 位优先，32 位兜底）、`ifSpeed`
  - 归一化：Device（名称/管理 IP/platform 由 sysDescr 解析）+ MetricPoint（if_*_bps/util，带 `speed_bps`、`clamped`、`source="snmp"`）
- 容错：单设备超时不影响其他设备；全部失败时 `reachable=false` 并降级
- 测试：单测用 mock SNMP 客户端（pysnmp 打桩）；如环境允许可用 `snmpsim` 本地模拟器做集成测试（可选，失败不阻塞）
- 前端/Agent 无需改动（数据形状不变）

## 五、前端（2 项 + 通知状态）

1. **路径追踪面板/入口**：选源/目的（从 hosts+devices 下拉）→ 调 `/api/path-trace` → 3D 场景中高亮路径（发光连线、hop 标记、断点红色 ✕）、面板列出 hop；支持清除。
2. **告警分组视图**：告警面板顶部切换「全部 / 按根因分组」；组卡片显示根因/设备/成员数/被抑制数，展开看成员；抑制成员灰显并标注「被上游抑制」。
3. **通知状态**：顶部或设置区显示「通知：已启用（webhook）/未配置」，提供「发送测试通知」按钮（调 `/api/notify/test`，显示结果）。
